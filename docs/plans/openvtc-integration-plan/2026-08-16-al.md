## 1. #229 → #236: the taskContext binding, promoted to the framework

Glenn reviewed #229, agreed with the digest-over-proofValue verdict, and —
because the PR's maintainer-edit flag was off (see §4) — carried it forward
as his own **#236, merged**: our witness-spec changes *unchanged in
substance*, plus the mechanism **lifted into the framework as §4.9.3** — a
citation relied on outside its exchange SHOULD carry a *task digest*:
`multibase(multihash(H(JCS(document ∖ proof))))`. Alberto credited as commit
co-author; the PR body names the analysis, attack table and trial as ours.

Upstream sharpened it in three ways worth absorbing:

- **The `proof` exclusion is principled, not a workaround**: §4.7 already
  excludes `proof` from what a proof covers, so the task digest and the
  document's own signature commit to the same content — one digest per
  document, signed or not.
- **Two normative implementation traps**: compare *decoded multihash bytes*,
  never encoded strings (`z`/`u` make one digest two strings); an
  unimplemented hash algorithm leaves the citation *unverified* — never
  substituted, never silently downgraded to id comparison.
- **Content, not authenticity**, stated plainly: a proof-stripped copy
  reproduces the digest by design; authenticity rests on the documents' own
  proofs (§4.7.1) and on the citing artifact signing the digest.

Also reconciled against the repo's other digest conventions (§7.2 item 11
document identity *includes* proof; ceremony-receipt step digest includes,
salted; §4.9.3 excludes) — each now cross-references the others.

## 4. Process lesson: maintainer_can_modify

#229 was created with `maintainer_can_modify: false` — `gh pr create` does
not enable it, which is exactly why Glenn had to re-cut instead of updating
in place. Rule going forward: after every upstream `gh pr create`, run
`gh api -X PATCH repos/<owner>/<repo>/pulls/<n> -F maintainer_can_modify=true`
(or tick "Allow edits by maintainers" in the PR sidebar — author-only).
