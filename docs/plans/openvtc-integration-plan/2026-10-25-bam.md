# 2026-10-25 — The embedded VTA is a deferred option, not a topology: decision on PR #52 (bam)

**Subtask:** [`embedded-vta_subtask.md`](./embedded-vta_subtask.md). **Reviewed:** [`2026-10-24-al.md`](./2026-10-24-al.md) (Alberto), which this adopts.
**Status:** Decision, applied to the subtask and the parent plan in the same commit.

## Decision

The **hosted agent is the default, and the best default.** The on-device (embedded) agent is a deferred, not-a-priority edge case. It is **not** a replacement topology and nothing is gated on it.

It is not closed either. The design keeps open the possibility of pure-mobile use for people who want it, and of emergencies in which no hosted agent is reachable. The subtask therefore stays, reframed as a **constraint on other work**: no design elsewhere may assume an agent that cannot run on, or move to, the phone.

## What is accepted

Alberto's evidence and disposition, in full: the limit is the phone's OS rather than connectivity (E1), comparable systems put an always-on server in front of the phone (E2), upstream's VTA has become one (E3), rooms need the member's agent reachable (E4), upstream's own phone agent approves for a hosted VTA (E5), phone hardware and the enclave are different grades (E6), and wallet `main` already ships the hosted model (E7). The evidence is not copied here; the subtask points at the companion.

Kept, as he proposed:

1. The present-user capability, offered as "On this phone" beside the hosted default, with the degraded behavior written into the subtask: requests while the phone is asleep show "Waiting for…" and "Expired before…" and never "failed"; rooms are unavailable in this mode because they need a reachable agent.
2. The phone as holder of the critical key share, following upstream's dual-unlock Option C.
3. Agent portability, as its own question.

## Gaps found in Part 1

- **The no-hosted-agent emergency case is not covered.** Part 1 offers "On this phone" as a choice made while a hosted agent exists, and its switch flow (U4) requires the phone online. It does not say what happens when the person chose hosted and the host is unreachable or gone. Recorded as an open question in subtask §9, with no design invented: whether the phone can take over temporarily, what it may answer, how it is entered, how it hands back.
- **Request lifetime and ownership** (his U6) remain unstated; recorded in §9 as well.

## Agent portability

Added as an open question to subtask §9 and, because it matters for every move regardless of this subtask, to the parent plan as §5.5. Not decided and not blocked.
