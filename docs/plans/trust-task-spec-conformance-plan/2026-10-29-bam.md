# 2026-10-29 — PR review of the conformance plan: `extends` is not registered by import (bam)

Parent: [`../trust-task-spec-conformance-plan.md`](../trust-task-spec-conformance-plan.md). Follows [`2026-10-28-bam.md`](./2026-10-28-bam.md).

## 1. Correction: importing a version module does not register `extends`

**Raised by** albertoleon7794 in review of the plan's PR: at `@openvtc/trust-tasks` 0.28.1, importing `trust-task-error/0.6/payload` does not register its `extends`, so `extendsChain('…/trust-task-error/0.6')` returns `[]` and `refused()` would still drop a 0.6 refusal.

**Verified** against the 0.28.1 package source installed in the shared checkout (`node_modules/@openvtc/trust-tasks/src`):

- `src/trust-task-error/0.6/payload.ts` exports `EXTENDS: string | null = "0.5"` and nothing that registers it.
- `src/_extends.ts` defines `EXTENDS_BY_TYPE_URI` as an empty frozen object.
- `src/_runtime/extends.ts` `defaultLookup` consults only that generated table and the tables registered with `declareExtends`. `declareExtends` is defined there and re-exported from `_runtime/index.ts`; no other file in `src` calls it. The CHANGELOG says generated code (from `trust-tasks-gen-ts`) calls it, which this package's own modules are not.

So the 10-28 plan wording ("import … which registers its `extends`", and P1's "costs one import") was an unchecked assumption and wrong. I had read the constant `EXTENDS` and inferred the library's index carried it.

**Applied:** plan §3 position 1 and W1 step 1 now register the 0.6 to 0.5 link at start-up (`declareExtends` with the map, or an explicit local index), and the W1 acceptance asserts `extendsChain(0.6 URI)` is non-empty and declares the synthetic 0.7 link in the test. P1 and P2 in the 10-28 companion carry a pointer here.

**Re-checked:** W1 step 2's `startsWith(TASK_ERROR)` readers do not use `extends`, so registration does not touch them; but whether `TASK_ERROR` is the version-free prefix could not be confirmed here (the 0.28 branch is not pushed and the code is not on this branch), so the plan now says to confirm it. Nothing else in the plan or the 10-28 companion relies on import-time registration; W10 step 3a asks about VTI's and openvtc's own readers, which is a separate question and unchanged.
