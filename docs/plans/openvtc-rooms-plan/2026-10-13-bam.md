## Errors in the drafts, independent of the baseline

Both baselines read the same here, so these were wrong when written.

- **Group messaging §6.1 and §6.3, the version race.** The host does not reject a
  create-only put of a new key over its version. It stamps `room.next_version`
  (`vti-rooms/src/storage.rs:451`), and the acknowledgement is `PutRecordResponse {key,
  version, epoch}`, which has no root (`vti-rooms/src/wire.rs:216`). A writer that loses the
  race finds out by comparing the acknowledged version with the version it sealed under. The
  stored record cannot be opened until it is rewritten. A retried `expectedVersion: 0` put
  returns a conflict with no record (`storage.rs:384–388`).
- **Merkle tree head (group messaging §12.1, S3 subtask).** `tree_head` scans and hashes
  every record on each call, and is deliberately uncached (`storage.rs:609–619`). It is not
  incremental.
- **S3 subtask.** Open-room cleartext is stored inline as `Record.cleartext`
  (`vti-rooms/src/lib.rs`). Relayed MLS commits are stored under a `room-commit:` prefix.
  `purge_record` and `curate_record` belong to the storage surface.
- **Encrypted Spaces subtask.** No `RecordStore` trait exists at the pin; the only store
  traits are `SessionStore` and `SeedStore`. `Store` and `KeyspaceHandle` are still closed
  enums (`Local`, `Vsock`), and the new `vti-common/src/store/test_fixture.rs` is test-only.
  In the ES prototype (aa7440b), `merk_storage` is in-memory only. Its only compare-and-swap
  is `commit_candidate` on the root of the whole tree.

## Still unverified

- Whether the wallet resolves a room's `did:webvh`, and whether it accepts the room's VIC,
  VMC and VAC with `issuerScope`. Nothing tests either.
- Whether a per-record writer signature is persisted. The guide says records are signed,
  but `Record` has an `author` and no signature field.
- Whether the Merkle tree head hashes body bytes or only stored fields. This decides whether
  S3 Option B must fetch bodies to compute a head.

## Decisions this raises

- **B3:** where the rooms client lives (above).
- **Group messaging §6.3, option B (bounded retry):** this is weaker than it reads. Each lost
  race leaves a record no one can open, and the rewrite takes a new version and can race
  again. Decide whether M0 measures these orphaned records and whether the sender retracts
  them.
