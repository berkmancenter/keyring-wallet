## 3. Reasoning behind the tool choices

**Property tests before models.** The pure functions in 2.5 are where upstream
interop breaks silently (digest drift, canonicalisation), they are cheap to
check, and `fast-check` runs in jest that already runs. Every other step
depends on the habit of stating a property, so the pilot is also a trial of that.

**Quint over TLA+.** Same underlying checkers (Apalache, TLC), but the team
writes TypeScript and Quint's syntax is close to it, so more reviewers can read
the model. Quint also generates traces, which is what makes replay (Step 2)
cheap. TLA+ remains the fallback and the plan says so.

**Replay is what makes the model worth keeping.** A model with no link to the
code stays correct only until the next edit to `WitnessTaskSessions.ts`. The
replay test turns "the model and the code disagree" into a failing test.
It does not prove the code matches the model beyond the generated traces; the
plan states that limit at Steps 1–2.

**ProVerif over Tamarin for admission.** Unlinkability between a token and a
session is an observational-equivalence property. ProVerif checks it directly;
Tamarin can with more effort. This is a judgement from the survey, not
something tried.

**Symbolic analysis now, not later.** The admission design has no code, so a
flaw found in the model costs a paragraph, not a migration. This is the main
argument for Step 4 and also its weakness: if the plan is built before the model
exists, the argument is gone.
