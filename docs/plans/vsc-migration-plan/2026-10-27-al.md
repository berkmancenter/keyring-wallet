# 2026-10-27 — §9 Q1 as shipped: the witness defaults to the VSC shape (al)

**Plan:** [`../vsc-migration-plan.md`](../vsc-migration-plan.md).
**Why this exists:** the witness on keyring-bifold `main` emits the VSC shape by default, while §6 V4 and §9 Q1 on this repository's `main` still say the default stays `wd02` until Q1 closes. The decision behind the shipped default was recorded only in companions on a branch that never merged. This file records it on `main`. It decides nothing new.

## 1. What shipped

**Concluded:** since keyring-bifold #403 (merged 2026-10-14), the witness server defaults to `WITNESS_CREDENTIAL_SHAPE=vsc`. `wd02` is a per-deployment opt-out.

**Evidence,** read at keyring-bifold `main`:
- `packages/witness-server/src/config.ts`, `loadConfig()`: `rawCredentialShape === 'wd02' ? 'wd02' : 'vsc'`. Unset, or any value other than `wd02`, gives `vsc`.
- `packages/witness-server/__tests__/unit/config.test.ts`: *"credentialShape defaults to vsc when WITNESS_CREDENTIAL_SHAPE is not set (pre-production flip, plan §9 Q1)"*.
- `packages/witness-server/README.md`: the shape is *"Selected by the `WITNESS_CREDENTIAL_SHAPE=wd02|vsc` config value, **defaulting to `vsc`** as of plan §9 Q1 (pre-production: no fleet to migrate, VWCs expire after 7 days)"*.

**How it reached `main`.** Two commits from the VSC migration chain, both carried by #403:
- `d0b122f0` (2026-09-27), the V4 cutover, added the switch defaulting to `wd02` (*"no behavior change"*).
- `2cf47d55` (2026-09-28), *"fix(witness-server): default WITNESS_CREDENTIAL_SHAPE to vsc"*, flipped it. Its own PR, keyring-bifold #218, was closed without merging; #403 replayed the chain onto `main`.

Neither commit was on bifold `main` before #403, so `main` never carried a `wd02` default. The app side of the migration (`@bifold/dtg-vocab` and the verification changes) is bundled by keyring-wallet #470, merged 2026-10-15; the first build tag that contains it is `staging-v0.2.0-251`. The witness default itself is server configuration, not app code. Which value a given witness deployment sets is not recorded here.

## 2. The reasoning given at the time

`2cf47d55`'s message, repeated in #218's description, gives four grounds:
- **Low risk now.** Keyring is pre-production.
- **No fleet to migrate.** Every VWC expires after 7 days.
- **No real community depends on the WD02 shape.** Only demo and test witness deployments exist.
- **§7.1's caveat is narrow.** The ecosystem's unmodified default `personhood.rego` checks the literal `WitnessCredential` type string, which a VSC-shaped credential does not carry. That affects only a deployment serving a community still on that unmodified policy, and such a deployment can set `WITNESS_CREDENTIAL_SHAPE=wd02`.

The same reasoning is in the comment above `credentialShape` in `config.ts`.

**The original companions.** Two dated companions on the migration branch, which reached keyring-wallet #259 (closed without merging), recorded the decision when it was made:
- `2026-09-27-bm.md` G3 (wallet commit `19ea65a7`): Q1's precondition met. The `verifiable-trust-infrastructure` fetch was repaired, and `personhood.rego` was re-read at pin `ed672fff`. The literal `"WitnessCredential" in cred.type` match was unchanged.
- `2026-09-28-bm.md` G11 (wallet commit `ca2372dc`): *"Q1 decided: `WITNESS_CREDENTIAL_SHAPE` now defaults to `vsc`"*. That companion also marked §9 Q1 resolved in its branch's copy of the plan, which never reached `main`.

**Who and when.** `2cf47d55` is dated 2026-09-28, and its author is the maintainer §9 Q1 names as the decider.

## 3. How this answers §9 Q1

§9 Q1 on `main` reads:

> **Q1 — Does V4 wait on upstream `personhood.rego`, or ship behind the switch?** §7.1 found a shipped upstream policy matching the WD02 type string, at a pin we cannot currently refresh. The plan's answer is the V4 config switch defaulting to `wd02`, which unblocks us without stranding anyone — but *when the default flips* is a judgement call about ecosystem readiness, not a technical one. **Blocked on:** repairing the `verifiable-trust-infrastructure` fetch and re-reading the policy.

Both parts are answered:
- **V4 shipped behind the switch.** It did not wait on upstream `personhood.rego`.
- **The default flipped to `vsc` on 2026-09-28,** after the precondition was met (G3 above). It reached bifold `main` with #403 on 2026-10-14. The stated ground was readiness: pre-production, no long-lived credentials to migrate, and no real community known to depend on the WD02 type string.

## 4. What it supersedes, and what it leaves standing

**Supersedes:**
- §6 V4's *"defaulting to `wd02` until §7.1's upstream question is closed"*. The default is `vsc`.
- §9 Q1 as an open question. It was answered as in §3.

**Leaves standing:**
- **§7.1's finding.** At the re-read pin, the shipped default `personhood.rego` matches the literal `WitnessCredential` type. A VSC-shaped credential fails that rule. A witness serving a community on that unmodified policy still needs `WITNESS_CREDENTIAL_SHAPE=wd02`.
- **The switch.** V4 says it is deleted when §7.1 resolves. That has not happened, and the switch remains in `config.ts`.

**Not done here:** the present-tense text of §6 V4 and §9 on `main` still describes the `wd02` default and an open Q1. Bringing it in line is a plan edit, and it cites this file.
