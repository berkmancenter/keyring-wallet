## Decided

1. **Epics carry an `epic` label, not an `Epic` issue type** (§4.2, view 4).
   - **Why.** An org issue type needs an org owner. A label in each repository does the same job for the board: view 4 filters on it, and sub-issues and their progress do not depend on the type.
   - **Supersedes:** "`Epic` (to be added)" in §4.2, and Step 0's "Add the `Epic` issue type".
2. **Automation runs as a bot account, not a GitHub App** (D10, §8, §8.1).
   - **Why.** An org-owned App needs an org owner to create and install it. A personal account's App installed on org repositories needs an owner's approval too. A separate GitHub user that the triage owner controls is the remaining way to keep a bot identity, not one person's account. It gets write access to both repositories and admin on the project, which repository and project admins can grant.
   - **Supersedes:** D10 as confirmed on 10-25, "automation runs as a GitHub App". The accountable role for the credential is unchanged: the triage owner owns rotation and revocation.
3. **Leak response without an owner** (§7.2, §7.3).
   - **What changes.** A leak in a body or comment is edited out and the old revision deleted from the edit history, which repository writers can do. A leak in a title, or a whole issue, still needs an org owner or a GitHub content-removal request.
   - **Why it is acceptable for now.** The scan runs before every write (§7.1), which is the main defence. Asking an owner to turn on member issue deletion is the one owner request this plan keeps.
4. **👍 sorting uses the README fallback** (§5). The view cannot sort by reactions.
5. **Step 1's source is a local rebuild.**
   - **What.** The review list was rebuilt from the agents' session records plus the coordinator's current queue, so Step 1 no longer waits on the claude.ai account that owns the Command Center. The product owner approved the list's publish / keep-private / drop decisions the same day, starting the board as fresh as possible.
   - **Supersedes:** Step 1's "Blocked" note.
6. **The triage and moderation owners are named**, privately. The plan stays role-only.
