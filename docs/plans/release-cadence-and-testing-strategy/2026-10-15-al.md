# 2026-10-15 — al — the VRC suites need debug builds

Companion to `gate_efficiency_subtask.md` (parent:
`../release-cadence-and-testing-strategy.md`, a local export). Written by the
gate lane on 15 October 2026, from the 241 re-pin's VRC run.

## What happened

On the re-pinned 241 (wallet `1f022308`, bifold `b880621b`, build 249),
`e2e:vrc` was run on that commit's CI test builds (test-builds run
`38656186728`, APK `0ef041ca`), Android emulator and iOS simulator. Both wallets
onboarded; wallet A opened its contact code and the QR rendered. The driver then
waited for `InvitationUrl` to read the invitation and paste it into wallet B,
re-entered the screen four times, and stopped: `element testID=InvitationUrl not
found in 60000ms`.

`InvitationUrl` is an E2E-only element, rendered only when `__DEV__`
(bifold `b880621b`, `packages/core/src/components/misc/QRScanner.tsx:488-497`).
The CI test builds are release builds (`keyring-release-test.apk`), so it never
exists in them. The run was not a verdict on the app.

## What follows

- Every suite that reads `InvitationUrl` (the `e2e:vrc` family, witnessed and
  device variants included) needs a local debug build of the pinned commit,
  with Metro from the same checkout, as `e2e/README.md` ("Build the app
  binaries first") already says. The plan's cadence section now states it.
- A debug build of both platforms is about 16 GB of output and 40 to 60
  minutes; it goes on a lane machine with room, scheduled with the release pin.
  For 241 it is run on the Mac mini, at the coordinator's direction, keeping
  the MacBook for other work.
- Rejected: exposing `InvitationUrl` in release test builds. A release build is
  what testers get; an E2E-only element in it is a change to the shipped
  surface for the harness's convenience.
