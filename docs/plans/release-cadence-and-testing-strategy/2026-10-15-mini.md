# 2026-10-15 — mini — the mini lane, and how lanes run

Companion to `gate_efficiency_subtask.md` (§5, phase 3, work-order item 10).
Written by the Mac mini lane on 15 October 2026, after setting up the mini and
reading the harness on `origin/main` at `65f74ade`. The coordinator answered
the open questions the same day; the project lead had approved the plan on
14 October.

## What was concluded

1. **`update-android` moves from the mini lane to the mac lane.** §5 placed it
   on the mini. Its setup joins the community with an approval and adds a
   second agent, so it needs runner B and the community's admin credential
   (`legs/update-android.sh`, its `need` line). The mini has neither, by
   design: its identity is a super admin on `keyring-runner-mini1` only, and
   no community admin credential is copied to it. The coordinator chose to keep
   the leg on the mac rather than give the mini B and a credential. Item 6 may
   reshape the leg later. `relaunch-android` has the same needs and merges into
   `update-android` (item 6), so it is not a mini leg either.
2. **The mini lane is Android only, on one runner.** Its legs today are
   `smoke-android` and `testreq` (main runner only, no credential), and
   `linkwait` and `linkresume` until item 11 moves them to ci. `devices`' screen
   rows join it once item 7 splits them off. `lostreq`'s nightly twin joins
   only if the twin needs no community credential. `pnmlink` stays off the mini
   until the gate lane confirms whether it needs admin on the no-rest agent
   or only its DID.
3. **No iOS on the mini for now.** Measured on the mini: a cold Android debug
   build (arm64 only) took the drive from 31 GB to 13 GB free. The 242 VRC
   run's Android phase left 13 GB, too little for an iOS build beside it,
   against the mini's 12 GB floor. Xcode 27 ships no Simulator.app, so iOS
   there runs headless (wallet #458, `E2E_IOS_HEADLESS=1`); it works (a WDA
   session reached the 241 app's Welcome screen in 58 s), but room is the limit.
4. **How a lane runs**, now in §5:
   - Each lane has its own environment file on its own machine, using the
     mac's variable names, so a missing runner fails a leg's `need` line at once.
   - Ports stay hard-coded, because no two lanes share a machine.
   - No lane sweeps or cleans keys on another lane's runner. This removes the
     two Farm-side clashes found in the harness: `gate_sweep` wiping another
     lane's rules, and `keys_since` deleting another lane's phone keys.
   - Each lane starts when its own builds are ready; lanes don't wait for each
     other (the coordinator's answer). The merged report waits for all of them.
   - A remote lane's run directory is copied back and merged into one report
     with a lane column. Reruns go to the lane that ran the leg.
5. **`PNM_HOME` must survive for a file-store identity.** `lib.sh` unsets
   `PNM_HOME` (the rule for the MacBook's pnm built from main, which reads it
   and fails when it's set). The mini's identity lives in a file store under
   its own `PNM_HOME` (`VTI_SECURE_STORE=file`), as the ci identity does, so the
   unset becomes conditional on the lane's environment.

## PR order for item 10

1. An environment file per lane (`E2E_LANE`, `env/lane-<name>.env`), with a
   test that a leg's `need` fails clearly on an unset `RUNNER_B_*`.
2. `PNM_HOME` kept when the lane sets `VTI_SECURE_STORE=file`; proven by one
   read-only `acl list` on `keyring-runner-mini1` from a leg's context.
3. `smoke-android` on the mini through its lane file, started by hand: the
   first gate leg on the mini.
4. `gate.sh run --lanes`: remote start, the pause reaching every lane, the
   start guards checked per machine, and the merged report and reruns.
5. One pin measured on mac and mini against a Mac-only run, row for row.
