# 2026-09-30: the closed mediator in the lab

Parent: [`../push-notifications-plan.md`](../push-notifications-plan.md)

The first lab run of the bundled mediator with its closed default
([2026-09-29-al.md](./2026-09-29-al.md), D14). It used:
- the package's own CI images (wallet #241);
- the push-test VTA on VTI main `32ddd2f2`, homed on the lab's Affinidi
  mediator (v0.33.1 + 3, `aa6d4ce8`);
- the bundled mediator (v0.33.1) on its own tunnel hostname;
- a new gateway identity minted on the lab's runner VTA.

Three things in the package were wrong, and are fixed there.

## Part 1: Findings

### F1. mediator-setup's admin identity can't log in on its own

`mediator-setup` writes the admin's `did:key` with its Ed25519 key only
(`admin-monitor.json`). Logging in authcrypts from the admin's DID, which needs
the X25519 key-agreement key `did:key` derives. Measured: the login fetched a
challenge six times and never answered it. `mediator-account` now derives the
key when it is missing; the login then succeeded. This is a candidate upstream
finding: upstream's own console reads the same file.

### F2. The closed default left the admin without an inbox

The mediator creates the root admin's account with `global_acl_default`
(affinidi-tdk-rs `55580615`, `server.rs` `seed_privileged_accounts`). With
D14's default the admin had no `LOCAL`. Measured: `GET /mediator/v1/ws` → 403,
"DID isn't local to the mediator".

### F3. The agent's next-hop account started closed

The gateway's reply makes the agent's DID a next hop, and its account is
created with the default. `DENY_ALL` gives it a closed access list. Measured:
"delivery blocked by the recipient's access list" and "recipient is not
accepting forwarded messages". The agent's `push/provision` timed out after
15 s, although the gateway had accepted it.

### F4. With the corrected default, the Farm-shaped path works

The flow, measured end to end:
1. push-test receives the `set-wake` at 17:34:23.51Z;
2. the lab mediator relays the signed `push/provision` to the bundled
   mediator's `/inbound` (17:34:24.49Z);
3. the gateway counts `provision ok`;
4. the bundled mediator relays the reply back (17:34:26.38Z);
5. push-test collects it at 17:34:26.57Z.

That is 3.1 s round trip. An unknown DID's login through the public tunnel
is refused with `403`.

Not measured yet: a wake to a phone, and the refusal of a stranger's forward
(`mediator-account --check-relay`).

## Part 2: Decisions

| # | Decision | Status |
| --- | --- | --- |
| D17 | The closed default is `DENY_ALL,LOCAL,SEND_MESSAGES,RECEIVE_MESSAGES,RECEIVE_FORWARDED,MODE_EXPLICIT_DENY`. `LOCAL` and `RECEIVE_MESSAGES` give the admin an inbox (F2); nobody without an account can log in to use them. `RECEIVE_FORWARDED` and `MODE_EXPLICIT_DENY` let an agent's auto-created account take the gateway's reply (F3). `SEND_FORWARDED` stays out, so no stranger's forward is relayed onward (2026-09-29 F5). **Supersedes** D14's default string; the rest of D14 stands | Decided; measured in the lab (F4) |
| D18 | `mediator-account` derives a `did:key` admin's X25519 key (F1). It also gains `--check-relay`, a no-login probe that sends a stranger's authcrypted forward naming a third party, and passes only on a refusal. CI runs it on every image, and the handover's go-live checklist has the operator run it | Decided |
| D19 | Agents' mediators must relay in upstream's default blind mode (single forward). A rewrapped or double forward names a sender that needs `SEND_FORWARDED` on the bundled mediator, and is refused. This is a requirement in the handover's §3 | Decided |
