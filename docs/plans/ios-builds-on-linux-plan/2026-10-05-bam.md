## TL;DR

| Option | Verdict for Keyring |
|---|---|
| **xtool** (open-source Xcode replacement on Linux) | No. SwiftPM-only; can't build an RN/CocoaPods app. |
| **macOS-Simple-KVM** | No. Dead since 2020, maxes out at Catalina. |
| **OSX-KVM** (maintained macOS-in-QEMU) | Works on a strong desktop. AMD GPU gives a fast simulator. With NVIDIA, builds work and headless simulator e2e probably works, slowly (unverified). ~1–2 year shelf life; violates Apple's EULA. |
| **Apple Silicon Mac mini** (used M1/M2, 16 GB) | Recommended. Cheap, legal, future-proof, runs headless. |
| **Cloud Mac** (GitHub Actions `macos-*`, EAS Build, MacStadium/AWS EC2 Mac) | Good for CI builds and TestFlight. |

## 1. xtool — https://xtool.sh / https://github.com/xtool-org/xtool

Legitimate project: MIT licensed, ~5.5k stars, actively developed, by Kabir
Oberai. It builds a SwiftPM package into an `.ipa`, signs it, and installs it
on a device from Linux, WSL or macOS.

Caveats (setup details come from prior knowledge, not checked against the
current docs):
- You supply `Xcode.xip` yourself, and it extracts the iOS SDK from it. The
  tool is open source; the SDK is Apple's, under Xcode's license.
- Needs an Apple ID. A free account works, but apps expire after 7 days.
- SwiftPM projects only: no `.xcodeproj`, storyboards or Interface Builder.
- No simulator; physical devices only.

**Why it doesn't work for Keyring, even with extra effort:**
- About 145 distinct pods (`app/ios/Podfile.lock`): RN core, Hermes, about 12
  Expo modules, `react-native-attestation`, `react-native-locality-peripheral`,
  the Askar native lib and more. Each would need a hand-written SwiftPM package
  with the right flags and headers.
- You'd have to replicate the Xcode build phases yourself: RN codegen, Metro
  bundling, Expo autolinking, `react-native-config`'s generated header, and the
  `.yarn/patches` written against Pods.
- `Media.xcassets`, the launch storyboard and the privacy manifest need
  `actool`/`ibtool`, which are macOS-only.
- Every RN/Expo upgrade would break it again.
- Still no simulator, so `yarn e2e:vrc` would still need a Mac. App Store
  uploads from a non-Xcode toolchain are also risky (SDK and Xcode metadata
  checks).

RN 0.81's prebuilt iOS core frameworks reduce the Hermes and core pain, but
most of the cost is the third-party and Expo modules.

Good for small standalone Swift apps. Not for Keyring.

## 2. macOS-Simple-KVM — https://github.com/foxlet/macOS-Simple-KVM

- Last code commit July 2020; no license file.
- Only High Sierra, Mojave or Catalina.
- RN 0.81 needs Xcode 16.1+, which needs macOS Sonoma 14.5+. App Store
  uploads now need Xcode 26, which needs Sequoia. **Can't build Keyring.**

## 3. OSX-KVM — https://github.com/kholia/OSX-KVM

The maintained successor (~23.7k stars, pushed January 2026). Runs
Sonoma and Sequoia on QEMU/KVM with OpenCore.

### On the laptop (i7-1355U, ~15 GB RAM): poor fit
- CPU is fine (Intel with VT-x).
- RAM is the problem: the VM wants 8 GB or more, and Xcode building 145 pods
  plus Hermes wants more. It will swap alongside Metro and the mediator.
- No GPU acceleration, so the iOS Simulator will be very slow.

### On a powerful desktop: can work well
| | Works well | Works with friction |
|---|---|---|
| CPU | Intel (mature OpenCore support) | AMD Ryzen: needs kernel patches, more fragile across updates |
| GPU | Supported AMD card passed through (RX 5000/6000): full Metal | NVIDIA: no modern macOS drivers, so software rendering only |
| RAM | 32 GB or more on the host, 16 GB or more for the VM | 16 GB host is tight |
| Disk | Dedicated NVMe or a large raw image | Xcode, simulators and DerivedData need 100 GB or more |

- **The GPU is what decides it.** Recent iOS Simulators rely on Metal. Without
  a passed-through AMD GPU the simulator is unusable, so you'd only be able to
  build and install onto a device.
- Physical iPhones over USB passthrough generally work, so building and
  installing for `yarn e2e:vrc:devices` is plausible.
- macOS updates can break OpenCore setups.

### NVIDIA desktop: build + headless simulator e2e only?

**Building iOS: yes.** Compiling, linking and signing don't use the GPU, so an
NVIDIA card is irrelevant. Give the VM plenty of cores and RAM.

**Headless simulator e2e: probably, slowly. Unverified.**
- macOS has no driver for the NVIDIA card. The VM only gets QEMU's virtual
  display, so it has no hardware Metal and everything renders in software.
- Evidence it works: GitHub's old Intel macOS runners were VMs without GPU
  passthrough, and iOS simulator e2e (Detox, Appium) ran on them, slowly.
- Evidence against: recent Xcode and iOS Simulator versions lean harder on
  Metal. It's unconfirmed whether current versions (Xcode 26, iOS 26 runtimes)
  boot and render properly in a QEMU VM with no Metal device. People report
  mixed results: black screens, slow boots, animations tripping test timeouts.
- Headless helps: boot with `xcrun simctl boot` and never open Simulator.app.
  The app still has to render for XCUITest/Appium, but there's less overhead.
- For `yarn e2e:vrc`, split the devices: run the Android emulator on the Linux
  host (NVIDIA-accelerated there) and only the iOS simulator in the VM, then
  point the Appium config at both.

**How to find out cheaply:** get the VM to the point of installing Xcode and an
iOS runtime, then `xcrun simctl boot` a device and run `yarn e2e:smoke`. If that
passes in reasonable time, `e2e:vrc` will most likely work too. If it hangs or
shows black screens, stop there.

### Shelf life
Apple has said **macOS 26 Tahoe is the last release supporting Intel Macs**.
All KVM approaches pretend to be an Intel Mac. Once Xcode requires macOS 27
(typically about a year after it ships), and App Store uploads require that
SDK, this route stops working. **Expect about 1–2 years at most.**

### Licensing
Apple's macOS license only permits macOS VMs on Apple hardware. Running it on
non-Apple hardware violates the license. It's widely done and rarely enforced,
but worth weighing for an institutional open-source project like Keyring.

## Recommendation

1. **Used Apple Silicon Mac mini** (M1/M2, 16 GB, a few hundred dollars).
   Fast simulator, legal, survives the Intel cutoff. Run it headless over
   SSH, with VNC for the screen.
2. **Cloud Mac CI** (GitHub Actions `macos-*`, or EAS Build since Expo modules
   are already in use) for builds and TestFlight. Keep day-to-day work on
   Android under Linux.
3. **OSX-KVM on the desktop**: only as a stopgap, only with an AMD GPU if you
   need the simulator, and accepting the license issue and the macOS 27 cutoff.
