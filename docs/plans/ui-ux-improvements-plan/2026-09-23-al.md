# 2026-09-23 — AL: seed by copy decided, and Join as creates a profile on the spot

**Plan:** [`../ui-ux-improvements-plan.md`](../ui-ux-improvements-plan.md). This document records a decision taken on 2026-09-23; it is not revised afterwards.

**Read at:** bifold `feat/join-as-profile` `170b05a6`; the profile screens from keyring-bifold#55 (`MyProfiles`, `EditRCard`) on main.

## Decision (AL, plan owner, 2026-09-23)

**A profile seeds a community's identity by copy, and the person can create a profile right at Join as.**

- *Join as* lists the person's existing profiles, with the active one chosen, and offers **Create a new profile**. That pushes the real profile editor (`EditRCard` in create mode) rather than a one-off form, and on return the new profile is chosen. In effect the person makes a card for this community.
- The chosen profile's details are copied **once** into the new community identity. There is no live link afterwards: editing the profile later changes nothing in a community.
- The vetting card's name is prefilled from the chosen profile, says which profile it came from, and can still be corrected.
- Both doors ask it — *I was invited* and *I want to join a community* — just before the identity is made.

**What it supersedes.** The editable multi-profile plan specifies an enforced 1:1 live link between a Keyring profile and a VTA persona. For **community identities**, that link is replaced by seed by copy. The 2026-09-22 companion recorded this as needing that plan's author's agreement; the plan owner decided it directly instead.

**Why.** Upstream's persona model reuses a face across communities only as a deliberate, warned choice, and protects people by keeping faces local. A live link would carry a profile edit into every community the profile ever seeded, which is exactly the correlation upstream warns against. Copying once gives the no-retyping benefit without that coupling. Creating a profile on the spot covers the person who wants a separate face for this community without leaving the flow.

**Where it is built.** keyring-bifold `feat/join-as-profile` (`useJoinAsChoice` / `JoinAs`, `vtiJoinSeed`, `EditRCard` registered in the My Agent stack). The plan's §5.2, §5.3, §5.8 and §8 describe it as current design.
