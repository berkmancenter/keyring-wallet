## 4. Findings about the tooling

### 4.1 The Test build's native id never saw the bifold native modules

`test-builds.yml` computes `native=` as a hash of `git ls-files -s app/ios app/android app/package.json yarn.lock bifold/packages/react-native-attestation/ios bifold/packages/react-native-attestation/android`. With `bifold` a gitlink, the two bifold pathspecs match nothing (a submodule's files are not in the superproject's index: `git ls-files -s bifold/packages/react-native-attestation/ios` prints nothing in the pre-fold checkout), so the id covered the app's native half only. After the fold the same command covers them, so the first folded Test build's `native=` differs from every earlier one although nothing native changed. Consequence: the gate never JS-swaps across the fold, which is the conservative direction; the hot-updater fingerprint (§2.1) is the one that must stay equal, and it is computed from the files themselves, not from the index. Recorded as a comment in the workflow.

### 4.2 Telling a gitlink from a tree

`git cat-file -t <rev>:bifold` fails for a gitlink (the commit object belongs to the submodule's repository, not this one), so it cannot distinguish the two eras. `git ls-tree <rev> -- bifold` prints `160000 commit …` or `040000 tree …` and is what `tier.mjs`'s `bifoldKindAt` and the gate scripts use. The tier tests' fixture also showed that `git add -A` drops a gitlink whose directory is not on disk; the fixture stages the gitlink-era commit by name.

### 4.3 The 280 cut range

`staging-v0.2.0-280..4a63610ab` grades `store` because `useBCAgentSetup.ts` (a MIGRATION_PATHS entry) changed in #955. That is the correct grade for the real 280→281 line, and it is why 281 is a store build of today's structure, not an OTA.
