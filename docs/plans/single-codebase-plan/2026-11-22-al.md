## 3. What the review found before the merge, and how each closed

Each row was fixed before `main` moved, with a test the review ran against the pre-fix code (the mutant) and saw fail.

1. **`js-only.mjs` read both sides of bifold before deciding a fold-crossing range** (natives and nativeInputs ran `git -C ./bifold ls-tree <pin>` against a directory that is no longer a repository, and `bifoldPin` threw on an absent bifold, which Phase 2 makes permanent). Fixed in #960 (83b21b66a): the crossing or absent case returns the full-build verdict before reading either side. The review's correction of its own row: the old bug was never an OTA safety hole, since the CLI's try/catch already gave FULL; the fix buys a legible verdict and no read of a repository that will not exist. Tests: the crossing with `./bifold` as the clone path and with a nonexistent one; the drop commit at an end; both ends absent.
2. **The ported `framework.yml`'s empty-diff guard compared two populations**: its whole-repository list was built with `--relative`, which filters the diff to `bifold/`, so every wallet-only PR into the integration branch read as "GitHub lists files, the diff is empty" and failed "Framework lint and format" at its third step. Hidden on #966 (which touched one bifold file), exposed by #968 (the first wallet-only PR), fixed there (e75aa7fca). The test selector, in the same job, got the same case right ("no jest suite").
3. **`tier.mjs`'s native-module rule was a two-name allowlist** while the Test build's trigger is the glob `bifold/packages/react-native-*/**`; a third `react-native-*` package's codegen specs in `src/` fell to the JS-bundle rule and graded `ota` (`react-native-foo/src/Foo.ts` → ota, measured). No live hole (only the two listed packages exist and are native). Fixed in #968: the rule is `react-native-[^/]+`, and a test reads every `bifold/packages/…` trigger path in `test-builds.yml` and grades a sample under each as `store`, so a native package added to the workflow under a new name fails the test until the rule learns it (the review's three mutants all fail it). The widening is a no-op on every path that exists or has existed here (7,084 paths checked).
4. **The selector's `--relative` guard fix had no test**: restoring the relative guard survived 17/17. Fixed in #971: the change reading is one exported function, `changedAgainst(base, { run, listed })`, with git injectable; three tests pin the wallet-only case, the control, and the `--relative`/`--name-only` pair of calls; four mutants fail it, including making both diffs the same shape again. Prettier flagged the new test file once (a reflow and an es5 trailing comma), and the red at step 8 skipped the step that runs these tests at step 14 while the three required names stayed green: a job rollup proves nothing about a step skipped behind an earlier failure, and a required-green rollup proves nothing about a non-required job. The merge waited for the step's own log (20 tests named).

Also fixed on the way: CLAUDE.md told readers to fetch `refs/replace/*` before any existed (now true, §1); the witness deploy script continued past a failed `cd` into the wrong compose file (it stops when `bifold/packages` is missing); the companion recorded a js-only limit that row 1 removed.

## 4. The e2e vrc red was the harness, on every build

Slot 1 and slot 2 (the fold's builds) failed `e2e:vrc` with `contact "Bob Baker" did not appear` while both phones' logs showed the exchange complete. Controls on pre-fold `main` 7571fc5d6 and on `main` 4cbf7e388 (the fold's bifold twin, same framework code) failed identically. The test lane found the cause: on a Release build the accepting side stays on the code screen, whose back control is testID `Back`, and `assertVrcReceived` tapped only `BackButton`; `pair-ios` already handled `Back`. The fix is wallet #969 (e2e only, merged as d75787c17 and so already on `main`); with it, vrc passes on the fold's own build (run 44954115049's artifacts) with a declared fixture deviation: the Android emulator ran on public DNS (`-dns-server 1.1.1.1,8.8.8.8`) because the mini's default resolver failed Android onboarding on both the fold's build and the `main` control before any app code ran. The nightly has no vrc leg, so no older baseline existed to compare with.

## 7. Lessons recorded for the next phase

- Pushes to a PR branch whose Test build is running cancel that build (`test-builds.yml`'s concurrency group): batch pushes between builds, and make the merge-grade build on the final head with nothing pushed during it.
- `git cherry-pick --abort` on a two-commit sequence rewinds both, including one already pushed; rebuild from the remote rather than force-push.
- Several `gh run watch` loops at their default interval exhaust the shared GitHub API budget (HTTP 403 at 22:10Z on 2026-11-21); one watcher at `--interval 180`, or none.
- A pull_request `branches:` filter names the PR's base, so PRs stacked on another fold branch need `fold/**` in the filters; `workflow_dispatch` works only for a workflow that exists on the default branch (404 otherwise).
- In the run-level log some steps render as "UNKNOWN STEP", so a grep for a step name there can be vacuous on a failing step; read the job-scoped log and check the denominator first.
