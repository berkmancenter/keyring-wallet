### 2. The `git am` recipes were wrong (plan §7.1 rules and sequence diagram, §5.3 back-port, §8 upstream)

- **Concluded:** bifold's patches name `a/packages/core/…`. `git am -p<n>` strips n leading components first and `--directory` is prefixed after. So: Phase 1 is `-p2 --directory=bifold/packages` (or `-p1 --directory=bifold`); Phase 2 is `-p2 --directory=packages` (a plain `git am` is equivalent there, since the paths already match). Wallet patches going back to bifold read `a/bifold/packages/core/…` in Phase 1, so `-p2` with no `--directory`, and `a/packages/core/…` in Phase 2, so a plain `git am` (`-p2 --directory=packages` also works). The plan's `-p3 --directory=bifold/packages` fails. Upstream Bifold's patches (plan §8) have the same `a/packages/…` shape, so `git am --directory=packages` alone writes `packages/packages/…` and fails; it needs `-p2`.
- **Evidence:** a scratch experiment in the session scratchpad (a bifold-shaped repo with `packages/core/src/{a,b}.ts`, and two wallet-shaped repos, one with `bifold/packages/…` and one with `packages/…`, each at the same base). One patch from `git format-patch` (new file `b.ts` and an edit of `a.ts`):

  | Direction and layout | Command | Result |
  |---|---|---|
  | bifold patch onto `bifold/packages/…` | `-p3 --directory=bifold/packages` (the plan's) | Patch failed |
  | same | `-p2 --directory=bifold/packages` | applied, files at `bifold/packages/core/src/` |
  | same | `-p1 --directory=bifold` | applied, same result |
  | bifold patch onto `packages/…` | `-p2 --directory=packages` | applied |
  | same | plain `git am` | applied |
  | same | `-p3 --directory=packages` | Patch failed |
  | same | `--directory=packages` alone | Patch failed (it looks for `packages/packages/…`) |
  | wallet patch (`a/bifold/packages/core/…`) onto bifold | `-p2` | applied |
  | same | `-p3` | Patch failed |
  | wallet patch (`a/packages/core/…`) onto bifold | plain `git am` | applied |
  | same | `-p2 --directory=packages` | applied |
  | same | `-p2` alone | Patch failed |

  Added to the plan: `git format-patch -1 <sha> -- <packages path>` for back-ports, so hunks outside `packages/` (the app, CI) stay out of a patch bifold cannot take.
- **Supersedes:** plan §7.1's `-p3` and its "`-p` strips" sentence, §5.3's `-p3 --directory=bifold/packages`, §8's `git am --directory=packages`; also Phase 1's acceptance "every open bifold PR's patch still applies with `git am` unchanged (the paths did not move)", which is false (the paths gain a prefix): now "applies with the Phase 1 form". AL's companion P2 repeats "applies unchanged"; it was not edited.
- **Plan sections changed:** §4 Phase 0 (new replay rehearsal) and Phase 1, §5.3, §7.1 (rules and diagram), §8.
- **Test impact:** new Phase 0 acceptance: replay bifold #1163 (`bdac5e5a0`, single parent, the first merge after the cut a5bfcf3b2; `gh api compare` shows #1163 and #1164 as the two commits between a5bfcf3b2 and 87805b240) with the Phase 1 form, then #1164 with the Phase 2 form after a `git mv`, check `git patch-id --stable` and file contents, and run one back-port each way. **Record the commands and output of that rehearsal here when it is run; it has not been run.**
