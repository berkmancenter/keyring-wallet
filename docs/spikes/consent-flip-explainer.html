Where consent lives in the relationship exchange

The 2026‑08‑18 authority flip moved the user's consent from each incoming credential to the relationship itself. Same wallets, same credentials, same mediator — one question instead of two, asked where it actually means something.

Before — legacy issue-credential 2.0

Consent was per-credential and implicit about the relationship: each user accepted the credential they were receiving, in a four-message exchange per direction. There was no way to decline the relationship — only to ignore an offer.

sequenceDiagram
    participant A as Alice's wallet
    participant B as Bob's wallet
    Note over A,B: connection established (didexchange)
    A->>B: VRC offer
    Note over B: Bob taps Accept (on Alice's credential)
    B->>A: request
    A->>B: credential -> Bob stores
    B->>A: ack
    B->>A: VRC offer
    Note over A: Alice taps Accept (on Bob's credential)
    A->>B: request
    B->>A: credential -> Alice stores
    A->>B: ack

After — trust-task propose + issue

Consent is answering the proposal, once, on the wallet that didn't propose (the proposer's user already consented by creating or accepting the invitation). On Accept, both signed credentials flow, are verified, stored, and receipted automatically. Decline is a first-class protocol answer.

sequenceDiagram
    participant P as Proposer's wallet
    participant R as Responder's wallet
    Note over P,R: connection established (didexchange)
    P->>R: propose { my relationship DID }
    Note over R: ONE prompt - "wants to form a relationship" - Accept / Decline
    R->>P: #35;response { accept, my relationship DID }
    P->>R: issue { signed VRC + proof } -> verified, stored
    R->>P: receipt { digest of what was stored }
    R->>P: issue { signed VRC + proof } -> verified, stored
    P->>R: receipt { digest of what was stored }

Why the flip was necessary, not just nicer

  1. One leg had to own the credential. Once the trust-task issue leg carried the signed VRC, keeping the legacy leg too meant every credential delivered twice and the user asked twice. Suppressing legacy removed the offer — and with it the old Accept button. Consent had to move somewhere.
  2. The old consent was semantically misplaced. Users were accepting credentials, but the thing being agreed to is the relationship — the credential is just its record. The plan makes this the design gain: who issues stops being inferred from transport artifacts and becomes a stated question with a stated answer.
  3. Atomicity. Two independent accepts allowed a half-formed state: one side stored, the other not. One answer now decides the whole exchange.
  4. Decline exists now. Legacy had no way to refuse a relationship, only to ignore an offer. The flip gives refusal a protocol shape: a trust-task-error, vrc/relationships/propose:declined.
